## Architecture

### What is Architecture, in this playbook?

**Architecture** covers the structural decisions that outlive any single feature - how services are split, how APIs are shaped, how layers talk to each other, and what "good" looks like before a line of business logic is written. Get architecture wrong and every subsequent decision (testing strategy, deployment, onboarding) inherits the pain.

In simple terms: **architecture answers the question, "How is this system put together, and why?"**

### Who is this for?

- **Architects** setting the technical direction for a new engagement
- **Tech Leads** reviewing designs against JMAN standards before build starts
- **Engineers** who need a consistent reference for API and service design conventions

### How to navigate

This chapter has one episode - **Standards** - covering general architecture standards and API design standards that apply regardless of stack.
