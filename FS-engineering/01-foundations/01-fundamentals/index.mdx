## Fundamentals

Foundational concepts every full-stack engineer on this playbook is assumed to know.

### Pages in this episode

| Page | What It Covers |
|---|---|
| [Full-Stack Architecture 101](./01-full-stack-architecture) | How a web request flows across the client, server, and database layers of a full-stack application. |
| [Git & Version Control Basics](./02-git-version-control) | Git tracks every change ever made to the codebase, who made it, and why — it's what makes it possible for many engineers to work on the same code at once without overwriting each other. |
| [APIs & HTTP Basics](./03-apis-http) | An API (Application Programming Interface) is the contract that lets the frontend ask the backend for something, or tell it to do something. |
| [Databases 101](./04-databases) | A database stores data so it survives after your application restarts. Two families are used in this org, and they solve different problems. |
| [Containers & Docker Basics](./05-docker) | "It works on my machine" is the problem containers solve. |
| [Environments & Cloud Basics](./06-environments-cloud) | An environment is a separate, isolated copy of the whole application (frontend + backend + database) running somewhere. |
| [CI/CD 101](./07-ci-cd) | CI (Continuous Integration) means every change is automatically built and tested as soon as it's pushed, so problems are caught in minutes, not weeks later. |
| [Testing 101](./08-testing) | Automated tests exist so a human doesn't have to manually re-check the entire application every time something changes. |
| [Security 101](./09-security) | Security in this playbook isn't a separate team's job done at the end — it's baked into everyday engineering ("shift left," see Vision & Principles principle #4). |
| [Glossary](./10-glossary) | Every acronym and shorthand term used elsewhere in this playbook, defined once, in one place. If you hit an unfamiliar term on any other page, check here first. |
