# Checklists & Templates

This section is a set of practical, repeatable references you come back to at specific moments in a project - kicking off, starting a feature, completing one, reviewing another engineer's work, or shipping a release - rather than reading once and moving on.

## What this section covers

| Page | What it answers |
|---|---|
| [Project Kickoff Checklist](/templates/project-kickoff) | An interactive checklist to clone and complete when starting a new full-stack project |
| [Project Start Checklist](/coding-standards/checklists/project-start) | What must be in place before writing any feature code |
| [Project Completion Checklist](/coding-standards/checklists/project-completion) | What to verify before marking a project or major feature complete |
| [JQAA Review Checklist](/coding-standards/checklists/jqaa-review) | The checklist the JQAA team uses to review a project against coding standards |
| [Release Checklist](/coding-standards/checklists/release-checklist) | What the Release Manager and Engineering Lead must verify before a go-live |

## Where this leads

These checklists enforce the standards defined throughout [Development & Coding Standards](/coding-standards/overview) and the [Delivery Lifecycle](/delivery-lifecycle/overview) at the specific moments they matter most.
