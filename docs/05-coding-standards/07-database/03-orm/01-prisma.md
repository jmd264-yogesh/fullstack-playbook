# Prisma Best Practices & Standards

Prisma is the recommended ORM for all new Node.js (NestJS / Express) projects. It provides strong type safety, migration-first development workflows, and excellent developer experience (DX).

## What to Implement (The "Dos")

### 1. Migrations First
- **Best Practice**: Always apply schema changes via migration files generated by Prisma. Never apply manual DDL changes directly to a shared database.
- **Example**: 
  ```bash
  npx prisma migrate dev --name add_user_status_column
  ```

### 2. Mandatory Connection Pooling
- **Best Practice**: Configure database connection pooling in your connection string to prevent exhausting PostgreSQL/MySQL connection limits.
- **Example**:
  ```dotenv
  DATABASE_URL="postgresql://user:password@localhost:5432/mydb?schema=public&connection_limit=10"
  ```

### 3. Database Column Mapping
- **Best Practice**: Always use `@map` and `@@map` to ensure database tables and columns follow the lower_snake_case convention while keeping camelCase in TypeScript.
- **Example**:
  ```prisma
  firstName String @map("first_name")
  
  @@map("users")
  ```

### 4. Soft Deletes Consistency
- **Best Practice**: Use `deletedAt DateTime? @map("deleted_at")` for soft deletes and always ensure queries filter out records where `deletedAt != null` unless explicitly looking for deleted items.

## What NOT to Implement (The "Don'ts")

### 1. Committing Credentials
- **Anti-Pattern**: Hardcoding connection strings inside `schema.prisma`.
- **Solution**: Always load values from the environment:
  ```prisma
  datasource db {
    provider = "postgresql"
    url      = env("DATABASE_URL")
  }
  ```

### 2. SQL Injection in Raw Queries
- **Anti-Pattern**: Using string interpolation inside `$queryRawUnsafe`.
- **Solution**: Always use tagged templates `$queryRaw` which automatically parameterize inputs:
  ```ts
  // Good (Safe from injection)
  const users = await prisma.$queryRaw`SELECT * FROM users WHERE status = ${status}`;
  ```

### 3. N+1 Query Issues
- **Anti-Pattern**: Querying relations inside loops.
- **Solution**: Use Prisma's `include` statement or batch query fetches.

## Setup & Installation

Install the Prisma CLI and Prisma Client library:

```bash
npm install prisma @prisma/client
npx prisma init
```

## Schema Definition

Define model structures in `prisma/schema.prisma`:

```prisma
// prisma/schema.prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql" // or "mysql" | "mongodb"
  url      = env("DATABASE_URL")
}

model User {
  id        String     @id @default(uuid())
  email     String     @unique
  firstName String     @map("first_name")
  lastName  String     @map("last_name")
  status    UserStatus @default(ACTIVE)
  createdAt DateTime   @default(now()) @map("created_at")
  updatedAt DateTime   @updatedAt @map("updated_at")
  deletedAt DateTime?  @map("deleted_at")

  orders Order[]

  @@map("users")
}

enum UserStatus {
  ACTIVE
  INACTIVE
  SUSPENDED
}
```

## Common Query Patterns

### Find Unique with Relations
```ts
import { PrismaClient } from '@prisma/client'
const prisma = new PrismaClient()

const user = await prisma.user.findUnique({
  where: { id: userId },
  include: { orders: true },
})
```

### Paginated List (Offset-based)
```ts
const users = await prisma.user.findMany({
  where: { deletedAt: null },
  skip: (page - 1) * pageSize,
  take: pageSize,
  orderBy: { createdAt: 'desc' },
})
```

### Short-lived Transactions (No external API calls inside!)
```ts
const result = await prisma.$transaction(async (tx) => {
  const user = await tx.user.create({ data: { email, firstName, lastName } })
  await tx.auditLog.create({ data: { userId: user.id, action: 'CREATE' } })
  return user
})
```

## NestJS Integration

Create a reusable `PrismaService` that manages your database connections:

```ts
// src/database/prisma.service.ts
import { Injectable, OnModuleInit, OnModuleDestroy } from '@nestjs/common'
import { PrismaClient } from '@prisma/client'

@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  async onModuleInit() {
    await this.$connect()
  }

  async onModuleDestroy() {
    await this.$disconnect()
  }
}
```
