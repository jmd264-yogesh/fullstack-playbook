# Role Path: Data Engineer / Analyst / Data-Oriented Roles

**Level:** 🟡 Intermediate - assumes basic technical/business context

## Why you need this playbook

The most important page on this path is not a data page - it's the one that explains when you should *not* reach for a data platform. Data professionals are often the first to propose a platform for a problem that a small application or automation would solve faster and cheaper. This path starts there deliberately, before getting into the technical depth you already know how to apply once a data platform genuinely is the right call.

## Reading list

1. [Application vs Data Platform](/business-foundations/application-vs-data-platform) - read this first. It is the most important page in the playbook for this role, and it works through the exact instinct ("we have data, let's build a platform") this path exists to check.
2. [Choosing the Right Solution](/business-foundations/choosing-the-right-solution) - the general framework this page's logic sits inside.
3. [From Manual to Digital](/business-foundations/manual-to-digital) - where a data platform sits on the wider solution spectrum, relative to scripts, automations, and applications.
4. [Data & Analytics Overview](/data-analytics/overview) - the full technical section: operational vs analytical data, warehouse vs lake, ETL/ELT, data quality, and governance.
5. [Basics: Databases](/basics/databases/overview) - the operational database fundamentals that underpin most "do we need a platform" decisions.
6. [Coding Standards: Database Overview](/coding-standards/database/overview) - engine and ORM-level standards once you're building against an operational database.
7. [Application vs Automation](/business-foundations/application-vs-automation) - the other common alternative to a data platform when the real need is a routine process, not analysis.
8. [Automation & Integration Overview](/automation-integration/overview) - API-based automation and scheduled jobs are frequently the actual answer to "how do we move this data."
9. [Case Studies Overview](/case-studies/overview) - real engagements showing when the answer was a purpose-built application or an integration, not a data platform.
10. [Measuring Business Value](/business-foundations/measuring-business-value) - how to frame a data initiative's value in business terms, not row counts or pipeline throughput.

## You'll know you're ready when you can answer

::: info Ready check
- Given a business problem, can you list the specific signals (multiple sources, volume, historical need, many consumers, governance, ML) that would justify a data platform here - and are they actually present?
- If none of those signals are present, what's the simpler alternative, and could you recommend it even though it's less interesting to build?
- What's the difference between operational data and analytical data in this specific system, and are you being asked to solve an operational problem with an analytical solution (or vice versa)?
- How would you measure whether a data platform you built is actually being used and creating value, six months after launch?
:::
