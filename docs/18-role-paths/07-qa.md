# Role Path: QA Engineer

**Level:** 🟡 Intermediate - assumes basic technical/business context

## Why you need this playbook

Testing well requires understanding what the system is actually for, not just what it does. This path pairs the business context with the concrete testing standards, so your test plans target the actual business risk, not just code coverage numbers.

## Reading list

1. [What is a Business Problem?](/business-foundations/what-is-a-business-problem) - understanding the real problem tells you what a "critical" defect actually looks like for this system.
2. [How Software Works in Real Life](/business-foundations/how-software-works-in-real-life) - a full transaction traced step by step is a ready-made map of test points.
3. [Delivery Lifecycle: Testing](/delivery-lifecycle/testing-phase) - where testing fits in the overall delivery flow.
4. [Testing Strategy](/security/testing/overview) - the test pyramid and coverage expectations used here.
5. [Unit Testing](/security/testing/unit-testing) - expectations for the lowest level of the pyramid.
6. [Integration Testing](/security/testing/integration-testing) - testing across API and database boundaries.
7. [E2E Testing](/security/testing/e2e-testing) - end-to-end flows, BDD, and Gherkin conventions used here.
8. [Security Guardrails](/security/security-guardrails) and [General Security Checklist](/security/security-checklist) - security is part of your test scope, not a separate team's problem.
9. [Quality Gates Overview](/quality-gates/overview) and [Testing Gates](/quality-gates/testing-gates) - what must pass before something can ship.
10. [Measuring Business Value](/business-foundations/measuring-business-value) - the baseline numbers (error rates, time saved) your testing should help protect.

## You'll know you're ready when you can answer

::: info Ready check
- What is the real business risk if this specific feature fails, and does your test plan reflect that priority?
- Where does your testing responsibility end and CI/CD automation begin?
- What's the difference between what unit, integration, and E2E tests are each responsible for catching here?
- What quality gate would block a release, and who owns overriding it if ever necessary?
:::
