# Role Path: Fresher / New Engineer

**Level:** 🟡 Intermediate - assumes basic technical/business context

## Why you need this playbook

You already know how to write code - this playbook isn't a programming tutorial. What it teaches is everything around the code: why the team builds things a certain way, how a feature actually gets from an idea to something running in production, and - increasingly important - how to recognize when the right answer isn't "write code" at all.

## Reading list

1. [What is a Business Problem?](/business-foundations/what-is-a-business-problem) - the habit of understanding the problem before reaching for a solution, which is the single most valuable thing to learn early.
2. [What is Full Stack?](/business-foundations/what-is-full-stack) and [How Software Works in Real Life](/business-foundations/how-software-works-in-real-life) - the mental model for how the layers you'll work in fit together.
3. [Choosing the Right Solution](/business-foundations/choosing-the-right-solution) - so you don't default to "build an app" for every request that comes your way.
4. [Basics: Full-Stack Architecture](/basics/full-stack-architecture) - the technical deep dive on the layers above.
5. [Basics: Git & Version Control](/basics/git-version-control/overview) - how code changes are tracked, branched, and merged here.
6. [Basics: APIs & HTTP](/basics/apis-http/overview) - the contract between frontend and backend.
7. [Basics: Databases](/basics/databases/overview) - how data is stored and queried.
8. [Basics: Cloud Computing](/basics/cloud/overview) - where all of this actually runs.
9. [Delivery Lifecycle Overview](/delivery-lifecycle/overview) - the end-to-end path a piece of work takes from requirement intake to hypercare.
10. [Development & Coding Standards Overview](/coding-standards/overview) - the concrete rules for your stack.
11. [Testing Strategy](/security/testing/overview) - why and how things get tested before they ship.
12. [Vision & Principles](/vision-principles) - the "why" behind the rules you'll be asked to follow.

## You'll know you're ready when you can answer

::: info Ready check
- If someone asks you to "build a dashboard," what questions would you ask before writing any code?
- Can you trace what happens, layer by layer, when a user clicks a button in the application you're working on?
- What is the difference between an application, an automation, and an integration - and could you tell which one a given request actually needs?
- Where does your code go after you commit it, and what has to pass before it reaches production?
:::
