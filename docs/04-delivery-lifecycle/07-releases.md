# Release Automation

This page covers the **automated release tagging and documentation workflow** used in our CI/CD pipeline. Every production deployment must be accompanied by a versioned GitHub release that is fully traceable to Azure Boards work items.

> **Looking for deployment strategies?** Blue/Green deployments, Canary releases, feature flag management, and zero-downtime database migrations are covered in the **[Deployment & Operations](/operations/overview)** section - not here.

## What This Page Covers

- Automated GitHub release generation tied to Azure Boards tickets
- Version tag creation and management
- Release notes automation from commit history
- Traceability from code commit → work item → production release

## Overview

- **Trigger**: Executes after the `build_docker_image` job completes successfully.
- **Environment**: Utilises tags generated by the build (`NEW_TAG`, `PREVIOUS_TAG`).
- **Platform**: `ubuntu-latest`.
- **Timeout**: 15 minutes per run.

## Step-by-Step Breakdown

### Checkout Code
```yaml
uses: actions/checkout@v4
with:
  fetch-depth: 0
```
Retrieves the full repository history so `git log` can compute the change range.

### Generate Release Notes
- Sets Azure DevOps PAT and repo metadata as environment variables.
- Determines the commit range between `PREVIOUS_TAG` and `HEAD` (or just `HEAD` for the first release).
- Scans commit messages for ticket IDs of the form `AB#<number>`.
- For each ticket, queries Azure Boards REST API to fetch the work-item title.
- Builds a formatted notes section linking commits to Azure Boards items.
- Falls back to a generic entry when no tickets are found.
- Appends a **Full Changelog** link when a previous tag exists.
- Exposes the notes via `$GITHUB_ENV` and adds a preview to the GitHub Actions summary.

### Create GitHub Release
```yaml
uses: ncipollo/release-action@v1
with:
  tag: ${{ env.NEW_TAG }}
  name: ${{ env.NEW_TAG }}
  body: ${{ env.release_notes }}
  draft: false
  prerelease: false
  token: ${{ secrets.GIT_TOKEN }}
  makeLatest: true
  allowUpdates: true
```
Publishes a signed GitHub release using the generated tag and attaches the dynamic release notes.

```yaml
create_release:
  runs-on: ubuntu-latest
  needs:
      - build_docker_image
  timeout-minutes: 15
  env:
      NEW_TAG: ${{ needs.build_docker_image.outputs.new_tag }}
      PREVIOUS_TAG: ${{ needs.build_docker_image.outputs.previous_tag }}
  steps:
      - name: Checkout Code
        uses: actions/checkout@v4
        with:
            fetch-depth: 0

      - name: Generate Release Notes
        id: generate_notes
        env:
            AZURE_DEVOPS_PAT: ${{ secrets.AZURE_DEVOPS_PAT }}
            GITHUB_REPOSITORY: ${{ github.repository }}
        run: |
            set -euo pipefail
            echo "Previous tag: ${PREVIOUS_TAG:-<none>}"
            echo "New tag:      ${NEW_TAG}"

            if [[ -n "${PREVIOUS_TAG:-}" ]]; then
              range="${PREVIOUS_TAG}..HEAD"
            else
              range="HEAD"
            fi
            commit_list=$(git log "$range" --pretty=format:"%h|%s")

            release_notes="## Updates"$'\n'
            ticket_lines=0
            while IFS='|' read -r commit_hash message; do
              [[ -z "$commit_hash" ]] && continue
              tickets=$(echo "$message" | grep -oE 'AB#[0-9]+' || true)
              [[ -z "$tickets" ]] && continue
              while IFS= read -r ticket; do
                ticket_no=${ticket//AB#/}
                ticket_title=$(curl -fsS -u ":${AZURE_DEVOPS_PAT}" \
                  "https://dev.azure.com/jmangroupltd/_apis/wit/workitems/${ticket_no}?api-version=6.0" \
                  | jq -r '.fields."System.Title" // empty' || true)
                [[ -z "$ticket_title" ]] && ticket_title="No title found for ${ticket}"
                release_notes+="- [${commit_hash}](https://github.com/${GITHUB_REPOSITORY}/commit/${commit_hash}) - ${ticket_title} ([${ticket_no}](https://dev.azure.com/jmangroupltd/_workitems/edit/${ticket_no}))"$'\n'
                ticket_lines=$((ticket_lines + 1))
              done <<< "$tickets"
            done <<< "$commit_list"

            if [[ "$ticket_lines" -eq 0 ]]; then
              release_notes+="- No Azure Boards updates in this release."$'\n'
            fi

            if [[ -n "${PREVIOUS_TAG:-}" ]]; then
              release_notes+=$'\n'"**Full Changelog**: https://github.com/${GITHUB_REPOSITORY}/compare/${PREVIOUS_TAG}...${NEW_TAG}"$'\n'
            fi

            {
              echo "release_notes<<__EOF__"
              echo "$release_notes"
              echo "__EOF__"
            } >> "$GITHUB_ENV"

            {
              echo "### Release notes preview"
              echo ""
              echo "$release_notes"
            } >> "$GITHUB_STEP_SUMMARY"

      - name: Create GitHub Release
        uses: ncipollo/release-action@v1
        with:
            tag: ${{ env.NEW_TAG }}
            name: ${{ env.NEW_TAG }}
            body: ${{ env.release_notes }}
            draft: false
            prerelease: false
            token: ${{ secrets.GIT_TOKEN }}
            makeLatest: true
            allowUpdates: true
```

## Why This Improves the Release Process

- **Single Source of Truth** - Tags are created by the build job; the release job consumes those tags, guaranteeing consistency.
- **Automated Traceability** - Commits referencing Azure Boards tickets (`AB#123`) are automatically linked to their work-item titles, eliminating manual copy-pasting.
- **Full Changelog Visibility** - When a previous tag is present, a direct compare link (`/compare/<prev>...<new>`) is added, helping reviewers see exactly what changed.
- **Continuous Documentation** - Release notes are generated on-the-fly and stored in the GitHub release body, ensuring documentation never drifts from the actual code changes.
- **Safety & Idempotence** - The job runs only after a successful Docker image build and respects a 15-minute timeout, preventing runaway pipelines.

> **Note:** Creating release tags is a mandatory step in the development lifecycle, and this page describes the automation used to enforce that process.
