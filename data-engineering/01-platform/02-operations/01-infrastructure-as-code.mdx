## Infrastructure as Code

**Reproducible Infrastructure** - If you can't recreate your platform from code, you don't own it-it owns you. IaC transforms infrastructure from fragile snowflakes into versioned, tested, reproducible assets.

Infrastructure as Code (<Term>IaC</Term>) enables declarative management of platform resources. Instead of clicking through UIs or running ad-hoc scripts, you define the desired state in code and let tooling make it so.

<Callout type="question">Can we recreate this environment from scratch using only code in version control?</Callout>

### Why IaC Matters

| Without IaC | With IaC |
|-------------|----------|
| "How did we configure prod?" | `git show main:terraform/prod` |
| Manual environment setup (hours) | `terraform apply` (minutes) |
| Configuration drift between envs | Identical environments guaranteed |
| Changes are untracked | Full audit trail in Git |
| Disaster recovery is a project | Disaster recovery is a deploy |

### State Management

| Approach | Pros | Cons |
|----------|------|------|
| **Remote Backend (S3/ADLS)** | Shared, locked, versioned | Setup required |
| **Terraform Cloud** | Managed, collaboration | Cost |
| **Local** | Simple | Not for teams |

### Decision Guidance

| Terraform | Native IaC | Scripts |
|-----------|------------|---------|
| Multi-platform infrastructure | Single platform focus | Terraform support missing (Fabric) |
| Team has Terraform experience | Simpler requirements | One-time setup tasks |
| Full GitOps workflow desired | Native tooling preferred | Complex conditional logic |
| Complex resource dependencies | Terraform gaps for specific resources | API-first operations |
