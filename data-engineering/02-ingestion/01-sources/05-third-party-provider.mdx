## External Data & 3rd Party

<Callout type="info">
  **Treat as Untrusted Input** - Third-party data is someone else's problem until it enters your platform. Validate, deduplicate, track freshness, and control cost. Every record has a price - sometimes literally.
</Callout>

### What this covers

D&B (Dun & Bradstreet), Experian, ZoomInfo, market data feeds, exchange rates, credit scores, weather data, partner data shares, and any data sourced from an external commercial provider.

### Characteristics

| Characteristic | Detail |
|----------------|--------|
| **Access method** | API, SFTP file drops, cloud data sharing (Snowflake Share, Delta Sharing), email delivery |
| **Schema control** | Provider-controlled - formats change with product updates and contract renewals |
| **Cost model** | Per-record, per-API-call, per-dataset, or annual licence. Full reloads can be very expensive. |
| **Delivery schedule** | Provider's schedule, not yours - delays are common during quarter-end and peak periods |
| **Data quality** | Variable - duplicates, outdated info, inconsistent formatting. Treat as raw input requiring validation. |
| **Licensing** | Data usage restrictions - may limit storage duration, downstream sharing, or geographic use |

### Common Pain Points

| Pain Point | Description | Example |
|------------|-------------|---------|
| **Cost per extraction** | Priced per record or API call. Full reloads are expensive. | D&B: full reload of 50K records costs significantly more than a 500-record delta. |
| **Unpredictable delivery** | Provider's schedule, not yours. Delays during quarter-end are common. | Market data delayed 2 hours during quarter-end. Morning reports used stale data. |
| **Variable quality** | Duplicates, outdated info, inconsistent formatting across deliveries. | ZoomInfo returns 3 records for the same company with different names and addresses. |
| **Licensing restrictions** | Data usage terms limit how you store, process, and share the data. | Contract limits data retention to 12 months. Team discovers 3-year-old records still in warehouse during audit. |
| **Format changes** | Provider changes file format, API schema, or delivery method during contract renewal. | D&B switched from SFTP file drop to API delivery at contract renewal. Three-week scramble to rebuild connector. |

### Cost Control Framework

<Callout type="warning">
  **Full Reloads of Paid Data are Money on Fire** - If the daily change rate is less than 1%, a full reload is wasting 99% of the cost. Always use incremental for paid sources.
</Callout>

| Strategy | When to Use | Cost Impact |
|----------|------------|-------------|
| **Incremental only** | Change rate < 5%, per-record pricing | Reduces cost by 90-99% vs full reload |
| **Change detection before request** | High per-record cost | Only request records that have actually changed |
| **Cached enrichment** | Enrichment data with low volatility (company info, credit scores) | Cache locally, refresh on a schedule (weekly/monthly) |
| **Tiered freshness** | Different data elements need different refresh rates | Company name: monthly. Credit score: weekly. Stock price: daily. |
| **Usage-based alerting** | All paid sources | Alert at 70% of budget threshold. Kill switch at 90%. |

### Data Sharing vs API

When available, cloud data sharing is significantly cheaper and more reliable than API-based extraction:

| Factor | API / SFTP | Cloud Data Sharing |
|--------|-----------|-------------------|
| **Latency** | Hours (batch) to minutes (API) | Near real-time (shared storage) |
| **Cost** | Per-record or per-call charges | Included in data subscription (usually) |
| **Maintenance** | Connector code, auth, pagination | Zero - provider maintains the share |
| **Schema evolution** | Manual handling required | Automatic - new columns appear in the share |
| **Platforms** | Any | Snowflake Share, Delta Sharing, Azure Data Share |

<Callout type="note">
  **Prefer Cloud Data Sharing** - When a provider offers Snowflake Share, Delta Sharing, or Azure Data Share, use it. Zero connector maintenance, zero API costs, near real-time freshness. Ask every provider: "Do you offer data sharing?"
</Callout>
