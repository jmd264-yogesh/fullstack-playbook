## Tooling

<Callout type="info">
  **Cost, Not Technology** - Tooling selection is not a technology decision - it's a cost, complexity, and maintenance decision. The right answer depends on how many sources you have, what type they are, whether JMAN has a reusable connector, and whether the project justifies adding a vendor.
</Callout>

### The Three Options

| Option | What It Is | Licence Cost | Engineering Effort | Maintenance |
|--------|-----------|-------------|-------------------|-------------|
| **Buy** | Managed SaaS connector (Fivetran, Lakeflow Connect, Snowflake OpenFlow) | Per-MAR or included in platform | Minimal (configuration) | Vendor |
| **Build** | Custom pipeline (Python, Spark, ADF Copy Activity) | Zero | High (weeks per connector) | Project team |
| **Reuse** | JMAN Marketplace connector | Zero | Low (deploy + configure) | Data Engineering CoE |

The default is NOT "always buy." The default is: **use the option that minimises total cost of ownership for the project's specific source mix.**

### Platform Ingestion Capabilities

Before choosing a tool, understand what each platform provides natively. The scoring below is from the [Platform - Ingestion](/platform/components/ingestion) assessment and determines how much external tooling a project needs.

#### Key Capabilities

| Capability | What It Measures | Why It Matters for Tooling |
|------------|-----------------|---------------------------|
| **Batch Ingestion** | Ability to ingest large volumes on schedule | Strong native batch = less need for external tools |
| **Native Connectors** | Pre-built connectors to common sources | Weak connector coverage = more likely to Buy or Build |
| **CDC Support** | Row-level change capture from transactional systems | No native CDC = must rely on partners (Fivetran, HVR) |
| **Schema Evolution** | Detect and apply schema changes without breaking pipelines | Poor schema evolution = more maintenance burden on any tool |
| **Error Handling & Retry** | Built-in failure detection, retry, and bad record isolation | Weak error handling = custom wrapper code regardless of tool |
| **Streaming Ingestion** | Near real-time ingestion with sub-minute latency | Niche requirement (~2% of JMAN projects) - weight accordingly |

<Callout type="warning">
  **The Scoring Drives the Tool Choice** - A platform scoring 2/5 on native connectors (Snowflake) needs a different tooling strategy than one scoring 5/5 (Fabric). Use the capability matrix above to quantify the gap, then fill it with the right Buy/Build/Reuse decision per source type.
</Callout>

### Tooling Checklist

| Assessment Item | Why It Matters |
|-----------------|---------------|
| Platform capability scores reviewed for ingestion | Quantifies native vs external tool need |
| Buy vs Build vs Reuse decision per source with rationale | Prevents default "buy everything" or "build everything" bias |
| JMAN Marketplace checked before building custom | Avoids reinventing solved problems |
| Managed tool only when 3+ SaaS sources, existing licence, or team lacks capability | Prevents vendor sprawl for marginal benefit |
| Tool aligned to platform (ADF for Fabric, Lakeflow for Databricks, etc.) | Platform-native tools have lower friction and cost |
