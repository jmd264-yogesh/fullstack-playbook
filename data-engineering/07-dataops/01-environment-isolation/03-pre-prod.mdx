## Pre-Prod

Pre-Prod is an **ephemeral** environment created immediately before a Production release. It mirrors Production data to validate that changes will not cause regressions.

#### Purpose

While UAT validates business logic, Pre-Prod validates technical integration:

* Row Count Analysis: Confirm no unexpected data loss (e.g., accidentally filtering out 50% of records)
* KPI Variance Checks: Verify that key metrics remain within acceptable thresholds (e.g., Revenue variance under 1%)
* Schema Compatibility: Ensure downstream dependencies are not broken

### Scope of execution

The continuous deployment (CD) process runs the latest code end-to-end against the mirrored production data.

-   **Starting Point:** Pre-Prod pipelines begin from the Production Raw Layer, not from source extraction. This avoids API rate limits and prevents duplicate data pulls.
-   **Exclusion:** Ingestion pipelines are excluded unless the release specifically targets ingestion logic.

### Automated Quality Gates
If regression tests detect variances beyond defined thresholds, the pipeline fails automatically and blocks the release. This prevents known issues from reaching Production.

### Handling large data volumes

A modern data platform provides Zero-copy cloning, which mirrors data without a physical copy. Leveraging zero-copy cloning speeds up
deployment.

### Teardown - Cleanup

After deployment completes (success or failure), the Pre-Prod environment is automatically dropped. This maintains catalogue hygiene and prevents stale environments from accumulating.

### FAQ

##### What is the difference between CI & Pre-Prod?
* CI – A process, not an environment. CI runs automatically when a Pull Request is opened. It validates code quality through linting, unit tests, vulnerability scans, and build checks. CI answers: "Is this code safe to merge?"
* Pre-Prod – An ephemeral environment spun up after CI passes, specifically for release validation. It mirrors Production data (via zero-copy cloning) and runs end-to-end pipelines to validate that numbers match. Pre-Prod answers: "Will this release break Production?"

| Aspect | CI (Continuous Integration) | Pre-Prod |
|--------|----------------------------|----------|
| What is it? | Process (automated checks) | Environment (ephemeral infrastructure) |
| When does it run? | On every PR/commit | Before Production release |
| What does it test? | Code correctness  syntax, unit tests, security vulnerabilities | Data correctness  row counts, KPI variance, schema compatibility |
| Data used | Mock, synthetic, or none | Cloned Production data (zero-copy) |
| Duration | Minutes | Minutes to hours depending on pipeline scope |
| Outcome | PR is mergeable | Release is deployable |
