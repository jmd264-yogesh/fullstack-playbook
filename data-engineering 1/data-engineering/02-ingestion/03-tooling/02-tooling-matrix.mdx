## Tooling Matrix

<Callout type="info">
  **The Platform Determines the Default Tool** - Start with platform-native capabilities. Only introduce external tools when the platform can't handle the source type or volume. JMAN Connectors fill the gap where managed tools are overkill and custom builds are wasteful.
</Callout>

### Strengths & Limitations by Tool

#### Fivetran

| Strengths | Limitations |
|-----------|-------------|
| 500+ connectors covering most SaaS sources | Per-MAR pricing can be expensive for high-volume sources |
| Automatic schema evolution and error handling | Limited control over extraction logic and scheduling |
| Fast setup - minutes per connector | Config-only - no code, can't customise behaviour |
| Excellent CDC for databases | File ingestion is limited compared to platform-native |
| Hybrid Deployment option for data residency requirements | Default SaaS model routes data through Fivetran's cloud - verify compliance before adopting |
| Webhook notifications for downstream orchestration | No DAG-aware orchestration - requires external orchestrator for end-to-end workflows |

#### Fabric - ADF

| Strengths | Limitations |
|-----------|-------------|
| Deep Azure integration (Dynamics, SharePoint, SQL Server) | JSON pipelines are hard to version control and review |
| Dataflows Gen2 for low-code ingestion | Limited native SaaS connectors (outside Microsoft ecosystem) |
| Event Grid for event-driven file processing | Complex CDC requires manual configuration |
| On-premises Data Gateway for hybrid scenarios | No built-in schema evolution |

#### Lakeflow Connect

| Strengths | Limitations |
|-----------|-------------|
| Native Databricks integration - included in DBU cost | Connector coverage still growing (fewer than Fivetran) |
| Automatic schema evolution with Delta tables | Requires Databricks workspace |
| Native CDC for databases | New product - less battle-tested than Fivetran |
| Code-first approach (Python, Git, CI/CD) | Complex sources may still need custom notebooks |

#### Snowflake OpenFlow

| Strengths | Limitations |
|-----------|-------------|
| Native Snowflake integration - included in credits | Early stage - limited connector coverage |
| Zero infrastructure management | No native API connector - partner tools required |
| Snowpipe for excellent file ingestion | Less flexible than code-based approaches |

#### JMAN Connectors

| Strengths | Limitations |
|-----------|-------------|
| Zero vendor cost | Coverage depends on Marketplace inventory |
| Tested patterns for common sources | Requires engineering capability to deploy |
| Full code control (Git, CI/CD) | Maintenance falls on JMAN CoE |
| Handles pagination, retry, schema evolution | May lack niche connectors |

### Platform Decision Matrix

<Callout type="note">
  **Match Tool to Source Type** - Don't let one outlier source drive the tool choice for all sources. Use platform-native for databases and files, managed tools only for SaaS sources that justify the cost.
</Callout>

| Source Type | Platform: Databricks | Platform: Snowflake | Platform: Fabric |
|---|---|---|---|
| **SaaS (3+ sources)** | Fivetran or Lakeflow | Fivetran | Fivetran |
| **SaaS (1-2 sources)** | JMAN Connector / Lakeflow | JMAN Connector / OpenFlow | JMAN Connector / ADF custom |
| **Database (CDC)** | Lakeflow Connect | Fivetran or OpenFlow | ADF linked service |
| **Database (query)** | JMAN Connector / notebook | JMAN Connector | ADF Copy Activity |
| **Files** | Auto Loader | Snowpipe + stage | ADF Copy Activity |
| **Custom APIs** | JMAN Connector / notebook | JMAN Connector | ADF Web + Copy |
| **3rd Party** | Delta Sharing | Snowflake Share | ADF + custom |
| **Unstructured** | Store ADLS + Unity Catalog | External stage | Blob Storage |
